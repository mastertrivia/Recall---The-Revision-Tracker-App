## 1. How to reach the bridge

All methods are exposed on `window.AndroidBridge`. They only exist when the
HTML runs **inside the Android shell** (WebView). In a normal browser the
object is `undefined`.

```js
// Safe accessor used throughout this doc:
const A = (typeof window !== 'undefined' && window.AndroidBridge) || null;
const hasNative = !!A;
```

**Threading / return values:** methods run on a background thread inside the
app. Methods that return a value (Boolean/String/Double) return synchronously
to JS. Methods that show UI (toasts, dialogs, file pickers) are dispatched to
the main thread by the shell — you do not need to do anything special.

**Error behaviour (global rule):** every bridge method is wrapped in a
`safe()` handler in Kotlin. On failure it records an entry in the native error
log and returns a safe fallback (`false`, `""`, `"[]"`, `"{}"`, `0.0`, or does
nothing for void methods). **A bridge call will never crash the app.**

## 2. Toast

### `AndroidBridge.showToast(message)`
- **Parameters:** `message` (String)
- **Returns:** void
- **Example:** `A.showToast("Session saved")`
- **Errors:** silently logged; no throw.

### `AndroidBridge.showToastLong(message)`
- Same as above but longer on-screen duration.
- **Example:** `A.showToastLong("Backup complete — 12 goals exported")`

## 3. Timer notification (the "live activity" notification)

The shell runs a foreground service with ONE persistent timer notification
(notification id 9001). **JS owns all timing.** The shell only draws the
notification text you give it and shows Pause/Resume/Stop buttons.

### `AndroidBridge.startTimer(title, text)`
- **Parameters:** `title` (String), `text` (String)
- **Returns:** void
- **Effect:** starts the foreground service + shows the notification with
  **Pause** and **Stop** buttons.
- **Gated by flag:** `timerNotificationEnabled` (default true). If off, does nothing.
- **Example:** `A.startTimer("Mathematics", "25:00 remaining")`

### `AndroidBridge.updateTimer(title, text)`
- **Parameters:** `title` (String), `text` (String)
- **Returns:** void
- **Effect:** updates the running notification (call this every second/tick).
- **Example:** `A.updateTimer("Mathematics", "24:59 remaining")`

### `AndroidBridge.pauseTimer(title, text)`
- **Parameters:** `title` (String), `text` (String)
- **Returns:** void
- **Effect:** updates the notification and swaps the **Pause** button for a
  **Resume** button.
- **Example:** `A.pauseTimer("Mathematics", "Paused at 24:59")`

### `AndroidBridge.stopTimer()`
- **Parameters:** none
- **Returns:** void
- **Effect:** stops the service and removes the notification.
- **Example:** `A.stopTimer()`

**Button taps** are delivered to your HTML as a `timerAction` event
(`"pause"` | `"resume"` | `"stop"`). See section 11.

## 4. Completion / one-off notifications

### `AndroidBridge.requestNotificationPermission()`
- **Parameters:** none
- **Returns:** void (result comes back as the `notificationPermission` event)
- **When:** call once, e.g. on first load, before showing notifications
  (required on Android 13+).
- **Example:** `A.requestNotificationPermission()`

### `AndroidBridge.showNotification(id, title, text)`
- **Parameters:** `id` (Int — reuse to replace, vary to stack), `title` (String), `text` (String)
- **Returns:** void
- **Effect:** posts a normal notification immediately (tapping it opens the app).
- **Gated by flag:** `notificationsEnabled` (default true).
- **Example:** `A.showNotification(1, "Goal complete", "You finished 'Read 30 min'")`

## 5. Alarms (fire even when the app is closed)

These use exact alarms + a dedicated alarm notification channel
(sound + vibration + a **Dismiss** button).

### `AndroidBridge.scheduleAlarm(id, triggerAtMillis, title, text)`
- **Parameters:**
  - `id` (Int) — your own id; reuse to reschedule, use with `cancelAlarm` to cancel.
  - `triggerAtMillis` (Number) — absolute wall-clock time in ms. Compute as
    `Date.now() + delayMs`.
  - `title` (String), `text` (String)
- **Returns:** void
- **Gated by flag:** `alarmsEnabled` (default true).
- **Example:**
  ```js
  A.scheduleAlarm(101, Date.now() + 25 * 60 * 1000, "Pomodoro", "Time is up!")
  ```
- **Note:** persistence across reboot is handled natively (alarms are
  re-scheduled on boot). Legacy path uses slot `sessionend` and a 60s duration.

### `AndroidBridge.scheduleAlarmWithSound(id, triggerAtMillis, title, text, soundSlot, durationMs)`
- **Parameters:** same as `scheduleAlarm`, plus:
  - `soundSlot` (String) — `sessionend`, `taskcomplete`, or `bombwarn`.
  - `durationMs` (Number) — ring window, clamped natively to 1–60 seconds.
- **Returns:** void
- **Effect:** persists slot + duration with the alarm. At fire time a silent
  notification is posted and `AlarmPlayer` plays the selected slot for the
  configured duration, even if the WebView is frozen or the process was killed.
- **Gated by flag:** `alarmsEnabled` (default true).

### `AndroidBridge.stopAlarmPlayback()`
- **Returns:** Boolean
- **Effect:** stops currently playing scheduled/in-app alarm audio immediately.
  Does **not** cancel future `AlarmManager` schedules and does **not** reset
  the Bomb timer.

### `AndroidBridge.cancelAlarm(id)`
- **Parameters:** `id` (Int)
- **Returns:** void
- **Example:** `A.cancelAlarm(101)`

### Checking alarm capability
There is **no** dedicated capability method. Read it from diagnostics:
```js
const d = JSON.parse(A.getDiagnostics());
if (!d.exactAlarmsAllowed) A.showToast("Exact alarms are restricted on this phone");
```

## 6. Storage (the real persistence layer)

JSON files in app-private internal storage (`filesDir/data`). This is your
source of truth; keep IndexedDB only as a working cache.

### `AndroidBridge.saveData(key, json)`
- **Parameters:** `key` (String — sanitised to `[A-Za-z0-9_-]`, max 100 chars), `json` (String)
- **Returns:** `Boolean` (true on success)
- **Example:** `A.saveData("goals", JSON.stringify(goalsArray))`

### `AndroidBridge.loadData(key)`
- **Parameters:** `key` (String)
- **Returns:** `String` — the stored JSON, or `""` if the key does not exist.
- **Example:**
  ```js
  const raw = A.loadData("goals");
  const goals = raw ? JSON.parse(raw) : [];
  ```

### `AndroidBridge.deleteData(key)`
- **Returns:** `Boolean`
- **Example:** `A.deleteData("goals")`

### `AndroidBridge.listDataKeys()`
- **Returns:** `String` — JSON array of keys, e.g. `["goals","settings"]`
- **Example:** `const keys = JSON.parse(A.listDataKeys())`

### Backup (whole-dataset, via system file picker)
- `AndroidBridge.exportBackup()` — void; v4.11: shows the native typed-confirmation dialog ("Export User Data"), then opens a "save file" dialog and writes ALL keys into one JSON file (FNV-1a checksum attached).
- `AndroidBridge.importBackup()` — void; v4.11: shows the native typed-confirmation dialog ("Import User Data" — type **IMPORT** to confirm), then opens a picker. The file is fully validated (app id, JSON shape, state structure, checksum) BEFORE any stored file is written — a bad file shows "Import failed: …" and changes nothing. On success the `backupRestored` event fires.

### App & Data menu (v4.11 — replaced the top-bar three-dot menu)
Each method opens the SAME native confirmation dialog the old menu used, then
performs its action. Triggered from Settings → Android Shell Settings → App & Data.

- `AndroidBridge.refreshApp()` — void; confirm ("Refresh App") → reloads the HTML. No user data is touched.
- `AndroidBridge.importHtmlFile()` — void; typed confirm ("INSTALL") → file picker; the HTML/ZIP is staged and validated before it replaces the current app. User data preserved.
- `AndroidBridge.revertHtmlFile()` — void; native typed-confirmation (type "ORIGINAL"), then deletes a custom-installed HTML interface and restores the bundled one (`html_user_imported` flag reset). User data directories are never touched. No-ops with a toast when the bundled HTML is already active.
- `AndroidBridge.exportCurrentHtml()` — void; confirm ("Save Current HTML File") → saves the CURRENTLY running `index.html` (bundled or custom-installed) as `goal-tracker-app.html`.
- `AndroidBridge.factoryResetUserData()` — void; typed confirm ("FACTORY RESET") → deletes user data only (storage, alarms, flags, sounds); the current HTML file is preserved. Keeps `auto-backup-before-reset.json`.
- `AndroidBridge.systemCheck()` — void; opens the native System Check dialog (full diagnostics + "Export as file").

## 7. Time safety (anti clock-tampering for running sessions)

### `AndroidBridge.elapsedRealtime()`
- **Returns:** `Number` — milliseconds since boot from a **monotonic** clock.
  Manual date/time changes cannot affect it.
- **Example:** `const t = A.elapsedRealtime()`

### `AndroidBridge.currentTimeInfo()`
- **Returns:** `String` — JSON `{ "wallMs": <number>, "monoMs": <number>, "bootId": "<uuid>" }`
  - `wallMs` — normal wall clock (`System.currentTimeMillis`), can be changed by the user.
  - `monoMs` — monotonic clock (same source as `elapsedRealtime`).
  - `bootId` — changes on every device reboot.
- **Usage pattern (verified contract):**
  ```js
  // at session start:
  const t0 = JSON.parse(A.currentTimeInfo());
  // later, to get trusted elapsed time:
  const t1 = JSON.parse(A.currentTimeInfo());
  let elapsedMs;
  if (t1.bootId === t0.bootId) {
    elapsedMs = t1.monoMs - t0.monoMs;              // trusted, tamper-proof
  } else {
    elapsedMs = Math.max(0, t1.wallMs - t0.wallMs); // rebooted: clamped fallback
  }
  ```

## 8. Feature flags (settings live in HTML)

Four known keys, all **default `true`**: `notificationsEnabled`,
`alarmsEnabled`, `timerNotificationEnabled`, `soundEnabled`. Native code checks
these before acting; your HTML settings screen reads/writes them.

### `AndroidBridge.getFlag(key, defaultValue)`
- **Parameters:** `key` (String), `defaultValue` (Boolean)
- **Returns:** `Boolean`
- **Example:** `const soundOn = A.getFlag("soundEnabled", true)`

### `AndroidBridge.setFlag(key, value)`
- **Parameters:** `key` (String), `value` (Boolean)
- **Returns:** void
- **Example:** `A.setFlag("soundEnabled", false)`

### `AndroidBridge.getAllFlags()`
- **Returns:** `String` — JSON object of all stored flags.
- **Example:** `const flags = JSON.parse(A.getAllFlags())`

### Display scale — v4.12 (stored in the same shell prefs, as a **string** value)
The app-owned "Display Size" setting: a 1–9 level picker where level `8` is the
app's normal size (as if the setting never existed), each level is ~8% apart,
and the default is `5`. The wrapper only persists the level; the HTML applies
it before first paint by rewriting its viewport meta (see the "Display Size
engine" script in `index.html`). Nothing here changes Android's system Display
size / Font size settings.

### `AndroidBridge.getDisplayScale()`
- **Returns:** `String` — one of `"1"`..`"9"` (default `"5"`, `"8"` = normal).
  Unknown stored values are reported as `"5"`. One-time migration: a value
  stored by the v4.11 1–10 scheme (no `displayScaleScheme` marker) is shifted
  +2 at first read so its visual size is preserved (old `8`/`9`/`10` clamp to
  `"9"`) and the marker `displayScaleScheme`=`"2"` is written. The 4-size
  names migrate through the same shift: `xsmall`→`"6"`, `small`→`"8"`,
  `medium`→`"9"`, `large`→`"9"`.

### `AndroidBridge.setDisplayScale(level)`
- **Parameters:** `level` (String — whitelisted: `"1"`..`"9"`, v4.12 numbering)
- **Returns:** void; unknown values are rejected and logged to the error log.
- **Effect:** persists the level (plus the scheme marker) so it survives HTML
  reloads and app restarts.

failure always falls back silently.

### `AndroidBridge.saveSoundFile(base64)`

- **Returns:** `Boolean` (false if > 1 MB or on error)
- **Example:** `A.saveSoundFile(base64String)`

### `AndroidBridge.playCompletionSound()`
- **Returns:** `Boolean` — false if no sound set, `soundEnabled` is off, or playback failed.
- **Example:** `if (!A.playCompletionSound()) { /* rely on notification sound */ }`

### `AndroidBridge.stopCompletionSound()`
- **Returns:** void

### `AndroidBridge.clearSoundFile()`
- **Returns:** `Boolean`

## 10. Diagnostics & error log

### `AndroidBridge.getDiagnostics()`
- **Returns:** `String` — JSON with verified keys:
  `shellVersion`, `androidRelease`, `androidSdk`, `device`,
  `notificationsAllowed`, `exactAlarmsAllowed`, `dataKeyCount`,
  `errorLogCount`, `customSoundSet`, `displayScale`, `useWideViewPort`,
  `loadWithOverviewMode`, `textZoom`, `fontScale`, `bootId`, `flags` (object).
  (`displayScale` is the app's Display Size level 1–9, v4.12 numbering; `useWideViewPort` /
  `loadWithOverviewMode` are the WebView viewport settings that must be `true`
  for the viewport-meta scaling to apply — Android WebView defaults them to
  `false`, which silently discards every sub-1.0 scale; `textZoom` is pinned to
  100 so the system font size never restyles the app; `fontScale` is the system
  font scale — informational only.)
- **Example:** `const d = JSON.parse(A.getDiagnostics())`

### `AndroidBridge.getErrorLog()`
- **Returns:** `String` — JSON array (oldest first, max 50) of
  `{ at, where, message }`.

### `AndroidBridge.clearErrorLog()`
- **Returns:** void

### `AndroidBridge.getShellVersion()`
- **Returns:** `String` — currently `"2.1"`.

## 11. Pending events (delivery + missed-event queue)

Native → HTML events are delivered by the shell calling:
```js
window.onAndroidEvent(name, payload); // you must define this function
```

**Verified events:**

| `name` | `payload` | Meaning |
|---|---|---|
| `notificationPermission` | `"granted"` \| `"denied"` | Result of `requestNotificationPermission()` |
| `backupRestored` | `null` | A backup was restored; re-read your data |
| `timerAction` | `"pause"` \| `"resume"` \| `"stop"` | A timer notification button was tapped |

If a notification button is tapped while Android has **killed the activity**,
the event is queued instead of lost. Drain it on load:

### `AndroidBridge.getPendingEvents()`
- **Returns:** `String` — JSON array of `{ name, payload, at }` (payload is a
  JSON string). Reading **empties** the queue (exactly-once delivery).
- **Required usage:**
  ```js
  window.addEventListener('load', () => {
    if (!A) return;
    JSON.parse(A.getPendingEvents()).forEach(ev => {
      window.onAndroidEvent(ev.name, JSON.parse(ev.payload));
    });
  });
  ```
